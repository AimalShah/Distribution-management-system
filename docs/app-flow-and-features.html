🏗️ Core System Architecture & Working Features

Overview of production capabilities currently functioning on the clean Turborepo monorepo.

Authentication & Multi-Tenancy
Working
Stateless HMAC bearer tokens, session middleware, and database-level multi-tenancy. Organization isolation is enforced across every single model.
  • Better-Auth integration with session token verification
  • Fallback auth token for local dev & testing (admin / admin123)
  • Every query scoped strictly by organizationId
  • User profile password update & active organization switching

Batch/Lot & FEFO Expiry (CP 07)
Working
First Expired, First Out inventory management. Batches are created automatically upon receiving purchases and deducted chronologically upon sales.
  • StockBatch tracking with remaining and received quantities
  • Automated FEFO sale deduction using earliest expiry date
  • Expiring Soon KPI card (configurable threshold, default 30d)
  • Dedicated Batches tab on Inventory page with status badges
GET /api/inventory/batches GET /api/inventory/batches/expiring GET /api/reports/inventory/expiry

Working
Tax calculation engine compliant with GST rules. Distinguishes intra-state (CGST + SGST) from inter-state (IGST) sales.
  • Tax rate support on product catalog (0%, 5%, 12%, 18%, 28%)
  • Automated CGST/SGST vs IGST split based on state matching
  • Printable HTML Tax Invoice with itemized tax breakdowns
  • Client-side Vector PDF invoice generation using jsPDF

🔄 System Flow & Entity Interconnection

How business transactions propagate across Suppliers, Inventory, Sales, FEFO deductions, Customer Ledgers, and Analytics.

1. Inbound Supply Chain & Batch Registration Flow
How new stock enters the system and establishes lot traceability
🏢 Supplier Creation
Create Supplier record with contact info, GSTIN, and credit terms.
➔
📦 Purchase Order Created
Operator enters items, unit cost, batch number, and expiration date.
➔
🏷️ StockBatch Ingestion
Creates StockBatch with received qty, remaining qty, and expiry.
➔
📊 Aggregate Inventory
Increments quantityOnHand and writes an InventoryLog audit row.
2. Outbound Sales, FEFO Deduction & Ledger Updating
The complete transaction loop from sale creation to financial balancing
👤 Customer Selection
Select customer, check credit limit, verify delivery state for GST.
➔
⏳ FEFO Deduction
System finds earliest expiring batch and decrements quantityRemaining.
➔
📑 Sale Invoice & GST
Computes CGST/SGST/IGST, creates invoice, marks initial status "UNPAID".
➔
💳 Customer Ledger (Debit)
Adds invoice total to customer's outstanding debit balance.
3. Payment Settlement & Reconciliation Lifecycle
Closing the transaction loop with payments or customer returns
💰 Payment Ingestion
Record payment via Cash, Bank, or Online against a specific invoice.
➔
🔄 Invoice Status Update
Invoice shifts from UNPAID ➔ PARTIAL ➔ PAID based on balance.
➔
📉 Customer Ledger (Credit)
Reduces outstanding balance; updates WhatsApp shareable statement.
➔
📈 Real-Time KPIs
Dashboard revenue charts and cash collections update automatically.
Entity A Relationship Entity B Business Action & Data Propagation
Organization 1 : Many All Entities Enforces tenant isolation. Every table contains organizationId.
Product 1 : Many StockBatch A product can have multiple batches arriving at different dates with varying expiry dates.
PurchaseItem 1 : 1 StockBatch Receiving a purchase item spawns a corresponding batch for expiration management.
SaleItem Many : 1 StockBatch Sale items decrement the oldest batch first (FEFO) to minimize inventory waste.
Customer 1 : Many Customer Ledger Sales increase ledger balance (Debit); payments and returns decrease it (Credit).
Sale 1 : Many Payment Supports multi-installment partial payments against sales invoices.

⚠️ Missing Features, Architectural Gaps & Roadmap

Honest audit of unbuilt capabilities, deferred checkpoints, and production enhancements required for full enterprise deployment.

🛑

Checkpoint 11: Configurable Return Policies & Automated Credit Terms Enforcement

While returns can be created manually and credit limits are saved on Customer records, the automated policy enforcement engine is Spec only.

  • No automated return-window cutoff (e.g., rejecting customer returns after 14 days)
  • No restocking fee deduction calculation on returned items
  • No automated order-blocking when a customer exceeds their Net-30 credit terms or overdue limit
Impact: High (Financial & Inventory Risk) • Status: Checkpoint 11 Pending
🎨

Checkpoint 12: Client-Customizable Invoice Layout Engine

The system currently provides one hardcoded standard Invenza Tax Invoice layout. Checkpoint 12 specifies customizable invoice templates.

  • No template selector (e.g. Classic vs Modern vs Thermal 80mm POS receipt layout)
  • No logo upload tool for dynamic branding in invoice headers
  • No user-configurable invoice terms & bank payment details in settings
Impact: Medium (Brand Customization) • Status: Checkpoint 12 Pending
📱

Automated WhatsApp Business Cloud API Integration

Checkpoint 16 implemented WhatsApp sharing via https://wa.me/?text=... protocol links, which requires an operator to manually click and send via WhatsApp Web/App.

  • No automated background webhook sending invoices to customer phones upon generation
  • No automated payment receipt dispatch via WhatsApp Cloud API
  • No two-way customer confirmation of statement receipt
Impact: Medium (Operator Productivity) • Status: Manual wa.me Link Only
🏭

Multi-Warehouse & Bin Location Management

Inventory is currently aggregated globally across the entire organization. There is no multi-warehouse partitioning.

  • No multiple warehouse support (e.g., Central Warehouse vs Branch Depot vs Store)
  • No inter-warehouse transfer orders (Transfer Order with In-Transit status)
  • No aisle/shelf/bin location tracking inside warehouses
Impact: High (For Multi-Location Distributors) • Status: Architecture Limitation
💻

Desktop Offline-First Sync Engine (Electron)

The Electron shell packaging passes builds and parity tests, but it acts primarily as a packaged Chromium browser window pointing to the live server.

  • No local embedded SQLite replica for zero-connectivity offline operation
  • No background sync conflict resolution when offline sales sync back to Postgres
  • No offline bill caching when retail internet drops
Impact: Medium (Retail Resilience) • Status: Checkpoint 05 Packaged Only
📷

Hardware Barcode / QR Scanner Integration

Currently, product codes, barcodes, and serial numbers must be entered by keyboard or bulk-imported via CSV.

  • No built-in camera barcode scanner stream in the POS page
  • No hardware USB HID barcode wedge scanner listener for rapid shelf audits
  • No barcode label generator/printer for newly received unlabelled goods
Impact: Medium (Warehouse Speed) • Status: Feature Opportunity
