# SKUs are server-generated from a per-Company format and immutable

Each product's SKU is generated by the server from a format the client configures per Company — tokens such as brand code, category code, and a padded sequence (e.g. `{BRAND}-{CATEGORY}-{SEQ:5}`) — and is immutable once the product is created. The sequence is per Company and never resets. Changing the format affects only products created afterwards; existing products keep their codes. A short `code` field is added to `Brand` and `Category` to feed the format, falling back to the first letters of the name when blank.

**Considered options:** a fully manual `productCode` (status quo) was rejected because it yields inconsistent, non-unique-looking codes; a globally fixed pattern was rejected because the client explicitly asked to define their own.

**Consequences:** `productCode` *is* the SKU; there is no separate `sku` column. Editing a product never changes its SKU. The format builder UI is still to build.

**Status:** accepted
